---
title: "Security and approvals"
description: "How Chat-Accounting keeps the MCP server local, authenticated, and unable to change your ledger without your say-so."
---

An AI assistant connected over MCP is a program acting on your books. Chat-Accounting is designed so that program can never reach your data from outside your machine, and can never post, reverse or delete a transaction without you clicking a button in the app.

## Network boundary

**Localhost only.** The server listens on `127.0.0.1`, never on `0.0.0.0` or your LAN address. Other devices on your network cannot reach it, and it is not exposed through your router. To let a remote assistant in you would have to set up your own tunnel, which this documentation does not recommend.

**Origin check.** Browser requests carry an `Origin` header. The server rejects any origin whose hostname is not `localhost`, `127.0.0.1` or `::1`. This stops DNS-rebinding attacks, where a malicious web page resolves its own domain to `127.0.0.1` and tries to drive your local server through your browser. Native clients such as Claude Code do not send `Origin`, so they are unaffected.

**Small requests only.** Bodies above 1 MiB are refused, and only `POST` and `DELETE` on the single path `/mcp` are accepted.

## Authentication

Every request must carry `Authorization: Bearer <token>`.

- The token is 32 random bytes rendered as 64 hex characters, generated by Node's `crypto.randomBytes` on first launch.
- It is compared with `crypto.timingSafeEqual`, so an attacker cannot learn it one character at a time by measuring response times.
- It is stored in the app's `electron-store` config file alongside your recent-files list. Anyone with read access to your user profile can read it, which is the same trust level as the company file itself.
- **Regenerate Token** in **Settings > AI (MCP)** replaces it instantly, clears every MCP session, and so disconnects every assistant until you update their config.

A wrong or missing token gets `401 Unauthorized`. The server does not reveal whether the token exists or is merely wrong.

## What the assistant can and cannot do

| Action | Allowed over MCP? |
| --- | --- |
| Read any document, report or ledger entry | Yes |
| Create a draft invoice, payment, journal entry, party or item | Yes |
| Edit a draft | Yes |
| Edit a submitted document | No. The tool refuses; the assistant must ask you to cancel first. |
| Create or change settings (singleton doctypes) | No. `create_document` and `update_document` reject singletons. |
| Submit a draft to the ledger | **Only with your approval in the app** |
| Cancel a submitted document | **Only with your approval in the app** |
| Delete a draft or cancelled document | **Only with your approval in the app** |
| Delete a submitted document | No. It must be cancelled (approved) first, then deleted (approved again). |
| Touch a company file other than the one open in the app | No |
| Change the MCP settings, token or port | No. These are only reachable from the settings tab, not over MCP. |

## The approval dialog

Three tools are marked **gated**: `submit_document`, `cancel_document` and `delete_document`. When one is called:

1. The main process brings the Chat-Accounting window to the front.
2. The renderer loads the document first. If it does not exist, the call fails immediately and you are not bothered.
3. The **Approve AI Action** dialog opens. It names the action, the document type and name, and shows the party, date, grand total and entry type where those fields exist, formatted the same way as in the rest of the app.
4. You click **Submit**, **Cancel Document** or **Delete** to approve, or **Deny** to refuse. Closing the dialog counts as deny.
5. Approvals are queued. If several gated calls arrive together, you see them one at a time and the dialog notes how many more are waiting.

The assistant receives `User declined the action in Chat-Accounting.` when you deny, or a timeout error if you do not respond within about two minutes. Either way the document is left exactly as it was.

<Warning>
Approval is per call. An assistant that wants to submit five invoices will ask you five times. This is deliberate. Read each dialog before clicking.
</Warning>

## Why create tools only make drafts

Every write tool except the three gated ones produces a document in **Draft** state. Drafts are visible in the app, can be opened and edited by hand, and have no effect on the ledger, outstanding amounts, GST reports or stock. If an assistant misunderstands you and creates the wrong invoice, nothing has happened to your accounts; you simply delete the draft, or let the assistant do so with your approval.

## Same validation as the UI

Tools run inside the renderer against the same `fyo` document model that the app's forms use. Required fields, link validation (the party and item must exist), GST template rules, journal balancing and number series all apply exactly as they do when you click **Save**. On top of that, the MCP layer adds its own checks:

- GSTIN must match the 15-character pattern, and may only be set for `Registered Regular` parties.
- HSN or SAC codes must be 4 to 8 digits.
- Journal entries must balance to within a millionth of a rupee before they are even created.
- Payments must target a submitted invoice with an outstanding amount, and the amount must be positive.

## Turning it off

If you do not want any assistant connected, click **Disable** on the **AI (MCP)** tab. The server stops, in-flight calls are rejected, and the choice persists across restarts. Nothing else in Chat-Accounting depends on the MCP server.
